# 怎样写一页 handbook

handbook 教三条工作流程：找到两次预训练运行从哪里开始分开（第 1 部分），
让 rollout 引擎和 trainer 一致（第 2 部分），让一个算子满足不变性（第 3 部分）。
第 0 部分讲三条流程共同依赖的概念。每一页是某条流程中的一步或一个概念。
实验是证据，放在报告里，不放在正文里。

## 读者是谁

懂 PyTorch、GPU 和 RL 训练的 ML 系统工程师，手上正有一个问题。
他读一页，是为了知道下一步做什么、为什么这样做。

## 一页的结构（d2l 的顺序）

1. **我们在哪里。** 一两句话，链接到上一步：读者现在手里有什么，还有什么不对。
   每部分的第一页说明整条流程要达到什么，并列出它的各个步骤。
2. **概念，先讲直觉。** 先用一个小例子或一张图讲清机制，再给规则：
   三个数按两种顺序相加；同一行在 batch 为 1 和 64 时；一个 decode 步对照一次 prefill。
   然后用一句话写出规则，并指出它是哪条通用原则的一个实例。
3. **这一步。** 按顺序写要做什么。每个动作写明：目标；怎么做（用哪个工具或 skill，一行，附链接）；
   成功是什么样子。多个选项用一张小表：选项、得到什么、代价等级、什么时候选。
4. **哪里会出错。** 坑用 `!!! warning` 提示框列出：一句原因，一句后果，一句该怎么做。
5. **小结。** 三到五条读者应当记住的要点。
6. **深入阅读。** 附测量结果的报告、代码、skill。

## 正文里不放什么

- **不放具体实验。** 不写 GPU 型号、驱动、库版本、模型尺寸、batch size 扫参、耗时、
  元素百分比、检查项的个数。这些放在 `examples/<name>/REPORT.md`。
  正文写一般规律（"行数变化时 cuBLAS 可能换一个 kernel，所以同一行在另一个 batch 里可能舍入不同"），
  并把报告作为证据链接过去（"实测：见报告"）。
- 不写 agent 是怎么做出来的，不写重试过程，不列逐个文件的清单。
- 解释性的句子里不放代码标识。工具名和 skill 名只出现在"这一步"和"深入阅读"里。

代价按等级写，不写数字："免费"、"小（百分之几）"、"中等（不到 2 倍）"、
"大（2 倍或更多）"，具体数字在报告里。
可以写出什么成立（逐位相等、满足 L2 不变性），但要链接到证据，
并用平实的话写明在什么条件下得到（"在一种 GPU 上得到"、"在两个节点、最多 16 个 GPU 上得到"）。

## 句子

- 一段只讲一个意思，段首就说出来。
- 术语第一次出现时给出定义，或者链接到术语表；同一样东西在每一页都用同一个词。
- 能用一张图（Mermaid）或一张小表说清楚结构，就不要写一大段文字。
- 不用宣传性的词，不写"只需"，不要一连串的限定语。

## 诚实

- 不要在措辞上削弱结果：逐位就是逐位；已知答案的演示就叫已知答案的演示；
  模拟出来的就说是模拟的。
- 没测过的内容要留在明处：如果它会改变读者的做法，就在正文写一行简短的"尚未证明"，
  完整列表放在待办事项里。

## 中文页

中文页按中文的写法来写，不要逐句翻译：章节、链接和代码与英文版相同；
语序用自然的中文；保留术语表规定的英文术语。句子要短。

## 完成前检查

- [ ] 页面开头说明读者在流程中的位置。
- [ ] 在给出任何规则之前，先用小例子讲清机制。
- [ ] 正文里没有硬件型号、版本、尺寸、耗时或百分比。
- [ ] 每个动作都写明了工具或 skill 和成功条件。
- [ ] 每个"什么成立"的结论都链接到证据。
- [ ] 中英两版的章节、链接和代码一致（`scripts/check_i18n.py`）。
- [ ] `mkdocs build --strict` 通过。
